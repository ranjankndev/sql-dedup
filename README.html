sql-dedup / sqlds

sql-dedup finds duplicate SQL patterns in a natural-language-to-SQL dataset. It also shows the SQL syntax that your dataset does not cover. It runs each query on your database to verify it. It does not change your data.

01 Purpose

Use this tool to make a training dataset for SFT or RL. Each item in the dataset is one pair: a question in natural language (NL) and one SQL query. The tool solves three problems.

PROBLEM 1

Duplicate patterns

You can write 2000 queries, but 600 of them can have the same structure. Only the values and names are different. These duplicates do not improve the training. The tool finds them and removes them.

PROBLEM 2

Coverage gaps

The tool has a checklist of 45 SQL syntax patterns. It shows which patterns your dataset does not use. Then it makes candidate SQL from your real schema for each missing pattern.

PROBLEM 3

Validation

The tool runs each new query on your real database. It shows the row count of each table and the result rows. Then it rolls back the transaction. Thus your data stays the same.

02 Architecture

The tool has one main command-line program and three library modules. The main program is sqlds.py. You can also use sqlpattern.py as a standalone program on dataset files.

ModuleFunction
sqlds.pyThe main CLI. It reads sqlds.json, keeps dataset.jsonl, and calls the other modules.
sqlpattern.pyMakes a structural fingerprint for each SQL query. Keeps the PatternIndex that finds duplicates. Also works as a standalone CLI.
sqlfeatures.pyHolds the checklist of 45 syntax patterns. detect() finds the patterns in a query. generate() makes a candidate query from your schema.
sqldb.pyConnects to SQLite or PostgreSQL. Reads tables, columns and foreign keys. Runs each query in a transaction and rolls it back.

03 Duplicate detection

The tool does not compare the SQL text. It compares the SQL structure. It parses each query into a syntax tree and changes the tree into a standard form. Two pairs with the same standard form are duplicates. The tool keeps the first pair and rejects the second pair.

Three levels

LevelWhat the tool makes the sameThese two queries are duplicates
exactSpaces, letter case, comments, the last ;select * and SELECT  *
templateThe items above, plus values. IN (1,2,3) becomes IN (?).age > 21 and age > 99
skeleton (default)The items above, plus names of tables, columns and aliasesSELECT name FROM users WHERE age > 21 and SELECT title FROM books WHERE price > 5

Use skeleton to get the most diverse training data. Set the level in sqlds.json. The table below shows the result for queries_221.json.

How the tool makes a fingerprint

0

Input query

SELECT name FROM customers WHERE city = 'Pune' AND age > 30;
1

Parse

sqlglot parses the query into a syntax tree. The tool removes comments and the last ;.

2

Mask the values (template, skeleton)

Each value becomes ?. A list of values becomes one ?.

... WHERE city = ? AND age > ?
3

Sort the AND / OR items (template, skeleton)

The order of the conditions is not important. Thus a AND b and b AND a give the same result.

4

Replace the names (skeleton)

Each table, column and alias gets a standard name in the sequence of its first use.

SELECT c1 FROM t1 WHERE c2 = ? AND c3 > ?
5

Write the standard form

The tool writes the tree as SQL text in lower case with single spaces.

6

Hash and look up

A SHA-1 hash of the text gives a 16-character key. The tool looks for the key in the PatternIndex. The result is NEW or DUPLICATE.

The names in step 4 are examples. The real standard form can look different.

NOTE

If sqlglot cannot parse a query, the tool uses a regex normalizer. Use --strict to change this. With --strict, an unparsed query is a duplicate only if the text is the same.

NOTE

One SQL structure can answer different business questions. For this case, use --nl-mode fuzzy. Then two pairs are duplicates only if the questions are also similar. The limit is --nl-threshold (token Jaccard, default 0.6).

05 Coverage and gaps

06 Procedure: make a dataset

You must have Python 3.10 or higher and sqlglot. For PostgreSQL, you must also have psycopg or psycopg2.

  1. Connect the workspace to your database. 
    python sqlds.py init --db demo_bank.db
# or: python sqlds.py init --db postgresql://user:pass@host:5432/mydb

    To get a demo database, run python make_demo_db.py first.

  2. Import your current pairs. 
    python sqlds.py import existing_pairs.jsonl --verify

    The tool accepts .jsonl, .json and .csv. It finds the field names automatically. It removes duplicates.

  3. Add new pairs one at a time. 
    python sqlds.py add --nl "Total balance per city for premium customers" \
  --sql "SELECT c.city, SUM(a.balance) FROM customers c JOIN accounts a ON c.id = a.customer_id WHERE c.segment = 'premium' GROUP BY c.city"
  4. Find the missing patterns. 
    python sqlds.py status
python sqlds.py gaps
  5. Make candidate SQL for each gap. 
    python sqlds.py suggest      # writes candidates.jsonl

    Write the question for each candidate. Replace the placeholder values with real business values.

  6. Import the candidates. 
    python sqlds.py import candidates.jsonl --verify
  7. Check a query manually (optional). 
    python sqlds.py verify --sql "SELECT ... FROM customers c JOIN accounts a ON ..."

    The tool shows the row count of each table and the result rows. It does not commit.

  8. Export the dataset. 
    python sqlds.py export --verified-only   # writes sft_dataset.jsonl {question, sql}

Other commands: schema shows tables, columns, keys and row counts. coverage shows the number of queries for each pattern.

07 Standalone tool

Use sqlpattern.py for a one-time job on a file. It does not need a workspace or a database.

python sqlpattern.py stats data.jsonl                     # duplicate % at each level
python sqlpattern.py dedupe data.jsonl --report report.json --html review.html
python sqlpattern.py build-index data.jsonl -o index.json
python sqlpattern.py check --index index.json --sql "SELECT ..."   # NEW or DUPLICATE
OptionFunction
--levelSet the level: exact, template or skeleton.
--htmlWrite an HTML report. Use it to see and filter the duplicate groups in a browser.
--save-indexSave the pattern index. Use it later with check.
--nl-mode fuzzyCompare the questions too.
--strictDo not use the regex fallback for unparsed queries.
--dialectSet the SQL dialect for the parser, for example postgres or sqlite.

09 Safety

WARNING

The option verify --commit writes DML changes to your database. Use it only when you want these changes. Do not use it on a production database.

CAUTION

Candidate queries from suggest have placeholder values, for example 'VALUE' or > 100. Replace them with real values before you add the pairs.

NOTE

Without --commit, each verification runs in a transaction that the tool rolls back. Your data does not change.

NOTE

The duplicate check uses the structure. Thus you can change the text of a candidate query. A small text change does not make a duplicate into a new pattern.

sql-dedup. The CLI files keep the names sqlds.py and sqlpattern.py.
